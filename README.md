# Видеостудия для ИИ-агента

Система для сборки и монтажа роликов, которой управляет ИИ-агент (Claude) через MCP,
а вы видите результат вживую в веб-редакторе и можете править руками.

- **MCP-сервер** — 15 инструментов монтажа: агент создаёт проект, раскладывает клипы, режет, ставит титры, экспортирует.
- **Веб-редактор** — медиатека, превью, таймлайн с дорожками, свойства клипа, журнал действий агента.
- **Рендер** — ffmpeg: итоговый MP4 (H.264 + AAC) в 9:16, 16:9, 1:1 или 4:5.

## Что нужно

- Node.js 20+
- ffmpeg и ffprobe в `PATH`

## Запуск

```bash
npm install
npm start          # веб-редактор: http://127.0.0.1:4321
```

MCP-сервер агент запускает сам. В Claude Code достаточно открыть эту папку — сервер описан в `.mcp.json`.
Для Claude Desktop добавьте в `claude_desktop_config.json`:

```json
{ "mcpServers": { "video-studio": { "command": "node", "args": ["/полный/путь/к/проекту/src/mcp.js"] } } }
```

После этого пишите агенту обычными словами, например:

> Создай вертикальный ролик из `/Users/me/video/talk.mp4`: убери паузы, поставь заголовок «3 ошибки новичков»
> на первые две секунды, добавь субтитры, подложи `/Users/me/music/beat.mp3` тихо на фон и экспортируй.

Редактор держите открытым: каждое действие агента сразу появляется на таймлайне и в журнале.

## Инструменты

| Инструмент | Что делает |
|---|---|
| `create_project`, `list_projects`, `get_timeline` | Проекты и их состояние |
| `import_media` | Видео, фото, аудио — по пути к файлу или по ссылке |
| `create_background` | Фон-картинка (цвет или градиент) для заставок и карточек |
| `add_clip`, `update_clip`, `split_clip`, `remove_clip` | Раскладка, подрезка, перенос, зум и наезд, скорость, громкость, фейды |
| `remove_silences` | Автомонтаж: вырезает паузы в речи и сдвигает остальное |
| `add_texts`, `update_text`, `remove_texts` | Субтитры, заголовки, плашки |
| `render_frame` | Возвращает агенту кадр-картинку, чтобы он проверил монтаж глазами |
| `export_video` | Итоговый MP4 или быстрый черновик |

Дорожки: `V1` — основной видеоряд, `V2` — перебивки поверх него, `A1`/`A2` — музыка и звук.

## Редактор

- Клип перетаскивается мышью, края тянутся для подрезки, клипы прилипают к соседям и к курсору.
- `Пробел` — воспроизведение, `S` — разрезать под курсором, `Delete` — удалить со сдвигом (`Shift+Delete` — оставить дыру), `←`/`→` — шаг в один кадр.
- Файлы загружаются кнопкой или перетаскиванием в медиатеку.

## Ограничения

- Генерации видео нейросетью и распознавания речи внутри нет: клипы берутся из ваших файлов, а текст субтитров
  агент получает от вас или пишет сам. Подключение внешнего сервиса генерации — следующий шаг, для него нужен API-ключ этого сервиса.
- Превью в браузере приблизительное (режим «размытый фон» показывается с чёрными полями, шрифт титров может отличаться); точную картинку даёт экспорт и `render_frame`.
- Редактор слушает только `127.0.0.1` и не имеет авторизации — не открывайте его порт в сеть.

## Проверка

```bash
npm test   # сквозной тест через MCP: импорт → вырезка пауз → перебивка → титры → экспорт
```

Проекты и экспорт лежат в `workspace/` (путь меняется переменной `STUDIO_HOME`).

# Парсер Threads (поиск похожих авторов через AdsPower)

Отдельный инструмент в этом же репозитории. Вы даёте референсные аккаунты, нажимаете «Парсинг» — и получаете список
похожих авторов, которые активно постят и собирают много комментариев.

Как он ищет:

1. Открывает каждый референс и берёт его самые комментируемые посты.
2. Собирает людей, которые комментировали эти посты (аудиторию ниши).
3. У каждого комментатора открывает список «Подписки» и запоминает, на кого он подписан.
4. Аккаунты, на которые подписаны сразу несколько комментаторов, — кандидаты. Чем больше пересечение, тем ближе ниша.
5. Каждого кандидата открывает и считает: подписчики, постов в неделю, лайки и комментарии на пост, дата последнего поста.
6. Кто проходит пороги — попадает в «Найденные». Одобренного можно одним нажатием сделать новым референсом, и следующий запуск пойдёт уже от него.

Парсер только читает: не лайкает, не подписывается и не комментирует. Единственное, что пишет в Threads, — ваш собственный
пост из блока «Новый пост», и только по вашему нажатию.

## Слежение за авторами (комментинг и воронка)

Референсы и все, кого вы одобрили («База авторов»), отслеживаются. Для каждого парсер открывает вкладку «Ответы» и запоминает,
что автор комментирует и у кого:

- вкладка **«Комментинг»** — лента: кто → кому, текст, когда, ссылка; новые с последнего запуска подсвечены;
- на карточке автора — сколько комментариев в день, доля повторяющихся текстов (признак шаблонного комментинга), у кого комментирует чаще всего;
- **«Воронка»** — куда автор ведёт из профиля: мультиссылка, OnlyFans, Telegram, Instagram и т. п., и сами ссылки;
- аккаунты, под постами которых ваши авторы комментируют (от 3 комментариев одного автора или от двух авторов), сами попадают в кандидаты.

«Обновить слежение» — быстрый запуск только по базе авторов, без поиска новых. В настройках («Объём и скорость») можно включить
автообновление каждые N часов: оно работает, пока открыта панель и запущен AdsPower.

## Постинг

Блок «Новый пост»: текст до 500 символов и, по желанию, одна картинка → «Опубликовать» → подтверждение. Пост уходит от аккаунта
из выбранного профиля AdsPower. Если публикация не подтвердилась, сначала проверьте в Threads, не появился ли пост, и только потом повторяйте.

## Запуск

Нужны Node.js 20+ и запущенный AdsPower с профилем, в котором выполнен вход в Threads.

```bash
npm install
npm run threads      # панель: http://127.0.0.1:4330
```

Без терминала: двойной клик по `start-threads.bat` (Windows) или `start-threads.command` (Mac).

В панели:

1. **AdsPower** → кнопка ⟳ загружает профили → выберите нужный. Если AdsPower требует ключ — «Подключение» → API-ключ
   (в AdsPower: Automation → API).
2. **Референсы** → вставьте `@username` или ссылки, по одному в строке.
3. **Парсинг**. Прогресс и журнал видны на странице, «Стоп» прерывает запуск, уже собранное сохраняется.

Первый запуск делайте с настройками по умолчанию (25 комментаторов, 30 кандидатов): он занимает около 10–20 минут.
Не ставьте большие объёмы и нулевые паузы — аккаунт, с которого идёт просмотр, может получить ограничение.

## Настройки

| Настройка | Что значит |
|---|---|
| Подписчиков от, постов в неделю от, комментариев на пост от | Пороги «активного автора». Кто не прошёл — во вкладке «Отсеянные» с причиной |
| Пересечение аудитории от | Сколько просмотренных комментаторов должны быть подписаны на кандидата |
| Только англоязычные | Пропускать комментаторов и авторов, которые пишут не по-английски |
| Ключевые слова | Дополнительный источник: авторы постов из поиска Threads по этим словам |
| Объём и скорость | Сколько постов, комментаторов и кандидатов смотреть за один запуск и какие паузы делать |

«Оценка» (0–100) складывается из пересечения аудитории и комментинга ваших авторов у кандидата (до 40), частоты постов (до 20), комментариев (до 25), лайков (до 10)
и подсказки по женскому имени (5). Пол и страну парсер не определяет — финальный отбор за вами: ✓ / ✕ на карточке.

## Данные и безопасность

- Всё хранится локально в `workspace/threads-parser/` (в git не попадает): `db.json`, аватары, `debug/`.
- API-ключ AdsPower лежит в `db.json` — не пересылайте этот файл.
- Панель доступна только с этого компьютера (`127.0.0.1`).
- Если что-то на странице Threads не нашлось, в `debug/` сохраняются скриншот и HTML — по ним чинится `SELECTORS` в `src/threads/threads.js`.

## Проверка

```bash
npm run test:threads   # поддельные AdsPower и Threads + настоящий Chromium: полный путь от кнопки до списка
```

Тест проверяет логику на имитации сайта: поиск, слежение за комментариями и постинг. На живом Threads через ваш AdsPower ничего из этого ещё не запускалось.
